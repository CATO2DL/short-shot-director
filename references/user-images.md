# 用户自带图片

## 接收与查看

用户可以带一张或多张照片、AI 图片、截图或既有首尾帧。先实际查看可访问图片，记录真实文件／资源、原始文件名与简短内容说明，以 U01、U02 等稳定 ID 标识。不能仅凭文件名推断内容；无法查看时说明缺失，请求可访问原图，不伪造检查结果。

不要求用户提供 n 组、m 个视角或重新生图。原图片可能是实拍、手绘或来源未知，缺少原模型、原提示词不会阻塞视频方案与交付。用户主动提供的来源信息按其说明记录，不冒称工具验证，也不凭画风猜模型。

## 确定首帧和模型

- 单图且用户说「用这张做视频」：可作为已选定首帧，记录该要求为依据，无须再问喜欢哪张。
- 多图且角色已明确：沿用用户指定的首帧、尾帧、身份或结构参考，检查一致性与工具支持情况。
- 多图用途不明：展示带 ID 的真实预览，询问首帧及其余图的角色，不把不同人物或产品随意归成同一组。
- 只作为风格参考的图：不自动认作首帧；需要生成场景时再转到 [候选流程](candidate-selection.md)。

每轮最多两个问题，通常优先问「视频使用哪个生成模型？」和「以哪张为首帧，其余图作什么参考？」；已知的跳过。自带图无需询问图片生成模型，只有需要实际补图／改图时才问。缺少运镜、画幅等按镜头设计规则补充，非阻塞项标为建议。

## 按需补图与混合来源

根据新可见面、身份一致性和目标工具判断是否补图。固定机位的轻微环境运动通常不需要补角度；大幅转头或环绕可能需要。说明具体缺口与可简化的运动方案，不默认补一整套视图。

用户决定补图／改图后，再询问图片模型，基于选定主图派生并另存版本，保留原图。未经要求不裁切、重绘或美化；输入不兼容时说明实际调整需要，按已有授权处理。真实产品未知侧面仍需可靠依据。

自带图与新生成图可混用，但逐张记录来源和父参考。自带图不计入本次新生成数量；若用户给出总目标数量，明确已有多少和需新生成多少，避免重复生成。

## 文件夹交付

按 [视频素材包规范](handoff-package.md) 复制选定原图，围绕实际图片编写完整视频提示词。自带图状态是「用户提供／已检查」或「用户提供／未检查」，不是本次已生成或待生成。

不知道原图片提示词时，逐图说明文件写「用户提供图片，原始生成提示词未知／未提供」，可附客观画面描述。实拍的图片生成模型为不适用。镜头文件第 4 节可给「根据当前图编写的重建建议提示词，非原始生成词、未执行」，不能冒称是该图的实际生成词，也不触发重新生图。

清单设 `input_mode` 为 `user_images` 或 `mixed`，自带图逐项设 `source_type: user_provided`。无分组时 `group_id` 为 null，未请求候选生成时 n、m 为 null。`image_model.verification` 写来源未知、用户提供或不适用（实拍），不伪造实际模型。未知原生成信息不自动阻塞已核实的视频输入包。

无法导出原图时标记缺少本地图片，不把仅含链接的包称为已含图片。交付包不等于生成视频，不自动上传到外部视频服务。
