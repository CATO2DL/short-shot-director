# 可直接使用的提示词

## 工具能力卡

完整方案的镜头文件可在参数表记录工具／版本（如已知）、能力来源及核实状态；精简素材包在会话中完成核实，仅将执行必要的模型、模式和文件角色写入 video.txt。来源可以是当前工具 schema、实际界面、官方文档或用户明确提供的配置。只核实本次要用的功能：时长与画幅、文字／图片输入、首帧／首尾帧／身份或多参考绑定、排除项输入方式。

图片生成模型和目标视频生成模型分别询问、分别填写。实际图片模型按每张工具结果记录；工具未披露时明确未知，不能从用户请求推定。选图完成后的视频提示词根据目标视频模型已核实的能力编写，视频提示词引用包内的实际图片文件名。模型与派生信息在当前会话中维护，不生成交付清单；保留的实际图片提示词与尚未执行的修订词明确区分，不把历史记录塞进最终包。

未知平台时填写「工具中立；能力未核实」。提供自然语言提示词、素材角色与条件性建议；不提供上传次序、槽位编号或某模式的执行步骤。不能把文档中的设计建议伪装成工具参数。

若已确认能力：

- 只支持文本输入：提供独立完整的视频提示词；首帧图片提示词是构图方案，不要求先生成图片。
- 支持首帧输入：说明选择实际已检查的哪份输入图及其角色，附视频提示词。
- 支持首尾帧输入：明确两帧来自同一主体与同一场景，先检查路径可达性、遮挡与光线一致性，再绑定真实文件。
- 支持多参考：按工具真实语义分配身份／场景／结构等角色。不假设所有图都是关键帧，不随意指定权重。
- 无独立负面字段：把关键限制写成普通语言并融入主提示词，例如「相机位置和高度保持不变」「只有一名人物」。有专用字段才给对应可复制内容。

## 静态图片提示词

一段完整提示词描述一个瞬间：主体数量与特征、位置与占比、前中背景、景别与起始视角、光向与明暗、主辅强调色用途、材质细节和必要排除项。不要要求静态图片「从正面慢慢转到侧面」，不要把向上摇的全过程写成一张图。

首帧与尾帧分别写各自的静态构图。补充视角明确基于哪份主参考、保持哪些身份／结构特征、改变什么角度。这是二维参考，不代表建好了三维资产。数字可集中标注为设计建议，再以自然语言强调视觉目标。

## 视频提示词

写成可单独复制的完整指令：用一句话建立场景与主体锚点，再描述开始、中段、结束；将相机轨迹、主体动作、环境运动分清；交代速度、保持条件与结尾停留。只重复会影响身份、结构或动态光影的静态特征，不机械复述图片形容词。

工具中立文本示例：

> 一名穿灰色长衣的人站在巨大浅色石墙前。一个连续镜头，建议约六秒。开始短暂停在墙脚与人物；随后相机保持原位置和高度，只缓慢抬高观看方向，人物从画面下沿退出。墙的竖缝向高处延伸，最后停在仍看不到墙顶的墙面。人物不走动，只有近地薄雾轻微横移。保持墙体结构与光照稳定，不切镜、不升高机位、不变焦、不增加人物。

时间段是节奏建议，不是精确到帧的 API 指令。总时长改变时同步各段分配，检查动作能否在短时内完成。结尾状态需要能由起始状态和规定运动连续到达。

## 提示词之间的依赖

| 修改 | 必须同步 |
| --- | --- |
| 主体数量、外观、服装或构图占比 | 参数表、首帧、相关派生图、视频身份锚点、素材有效性 |
| 主色变暖 | 主辅色关系、光源色与明暗、材质反射、首尾图与视频保留条件 |
| 相机角度 | 起始图、可见面、补图需求、遮挡、结束构图与视频方向 |
| 主运动或幅度 | 相机字段、开始／中段／结束、尾帧、排除要求、验收条件 |
| 身份参考更换 | 所有依赖旧参考的派生角度和起始／结束图 |

完整提示词中不要保留「暖金色」与「全片冷蓝」等旧矛盾，也不要让「固定机位」与「缓慢推进」同存。用户只改一项时，其他已经确定的设计保持稳定；只有依赖受影响才改动。
