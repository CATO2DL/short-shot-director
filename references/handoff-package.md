# Markdown 交付与临时文件

## 一步写最终文档

直接使用 [简洁模板](../templates/shots.md) 写一份 `shots.md`，不先制作 11 节方案再转换。每个镜头依次包含：`镜头 1｜名称`、具体建议秒数、一张或几张必要视角图片、完整视频提示词。一个镜头不扩充为多个；多个已指定短镜头汇总到同一文档，候选组不当作镜头。

建议时长按动作与节奏给出，服从用户要求和已确认的工具限制。图片标明首帧、尾帧或辅助参考；只有确需且目标工具支持时才给相应绑定说明。视频提示词可独立复制，分清相机、主体、环境运动和起止状态。模型、模式、画幅只写执行所需的一行信息；如需图片提示词也放在对应镜头下，不另开文件。

用户只要提示词时不生图，缺图写「图片：待生成」。原图没有生成词时不杜撰。未知工具用工具中立版本，不编造模型、时长档位、参考槽位或能力。没有实际生成视频就不声称已完成视频。

## 最小文件集合

```text
shot-delivery/
  shots.md
  images/
    shot-01-start.jpg
```

上述仅为目录示意。只写真实图片的 Markdown 嵌入链接，使用相对路径，原图格式不改；同一图片可被多个镜头引用，避免重复复制。只放文档引用的必要图，不带无用角度或对比图。用户阅读入口是 Markdown；images/ 是显示图片所必需的附件。聊天图片预览仍遵循宿主的绝对路径要求。

默认不创建 README、manifest、日志、候选表、来源说明、模型追踪、用户原话备份、独立提示词文件、旧版副本或额外预览。不要为了检查文档而落盘一套无用 HTML／PDF／截图；如工具确需临时产物，检查后清理。用户明确要求详细方案时才另用详细模板。

默认直接提供 Markdown 链接。用户要求 ZIP 或当前下载方式确需整体打包时，只生成一个含 Markdown 与必要图片的最终 ZIP，放在输出目录外，不另建压缩中间包或校验文件。用户明确要求物理单文件时先核实阅读器是否支持内嵌图片；不默认写入庞大 base64，也不删除附件造成图片失效。

## 生命周期与清理

1. 本轮必要候选、派生图和工具中间产物集中在专用临时目录，记住具体文件归属，不生成记录文件。用户原图直接读取，确需编辑或交付时才复制；不为每步自动备份。
2. 用户选择之前保留有效候选；工具仍运行、派生仍用到父图时保留对应依赖。用户明确要求保留的候选不清理。
3. 选定后只把必要图片转存到最终 images/，写好 Markdown，确认图片可读、内容未丢失、所有引用有效；确认工具和派生步骤已结束。
4. 再删除本轮明确创建、已无依赖的未选候选、失败图、重复副本、临时提示词、拼图、预览与旧中间文件。如在修改同一个交付目录，只清理本轮已替换且无引用的旧文件；未确认归属的历史文件不动。
5. 删除只针对已知具体文件或确认完全由本轮持有的临时目录，不递归跟随符号链接，不扫描用户目录按名称批量删除。不要碰用户原图、最终引用图片、其他任务或共享工具缓存。不能确定归属就保留并简短说明。
6. 清理后再次检查 Markdown 引用；如有 ZIP，确认解压后引用有效、内容与最终文件一致。不要删除供用户下载的最终包。

清理只适用于可控的本地本轮产物，不擅自删除远程服务记录或图床资源。没有临时文件可删就结束，不为表现清理过程创建日志。技能源码的指南、模板、示例、许可证与正式发布附件不属于任务临时垃圾。

## 验证与交付

确认每个镜头具备名称、建议秒数、必要真实图片（或待生成状态）及完整提示词，图片角色与模型能力相符。能直接预览时检查渲染；否则检查文件与引用，不声称视觉验证通过。缺图、未核实能力或未完成视频在回复中简短说明，不另写状态文件。最终只给用户实际需要的文档与附件。
