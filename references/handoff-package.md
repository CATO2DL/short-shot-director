# 给视频生成 AI 的交付文件夹

## 创建时机与目录

用户明确选定候选组和首帧，或已直接提供选定图片后创建最终交付文件夹。候选图生成期间可以使用工作目录，但必须标为候选，不能提前标记用户已选择。未完成选择时停留在选图阶段。

在用户指定位置或当前项目输出目录中创建有意义的独立目录，例如 `S01-cloud-palace-video-kit-v1/`。以下是命名规范，不表示这些图片已经存在：

```text
S01-cloud-palace-video-kit-v1/
  README.md
  shot.md
  manifest.json
  images/
    G02-V01.png
    G02-V02.png
    G02-V03.png
  prompts/
    original-user-prompt.txt
    images/
      G02-V01.txt
      G02-V02.txt
      G02-V03.txt
    video.txt
```

文件扩展名使用真实格式，不把 JPEG 字节直接命名为 PNG。原图名、组号、视角号和版本需能互相追溯；同名包已存在则递增版本，不覆盖用户修改或旧版图片。

自带图按 [自带图片流程](user-images.md) 使用 U01 等 ID，无须强行分组。下文「选定组」在此指用户明确选定的素材集合，文件可对应为 U01.jpg、U01.txt 等。

## 放入哪些内容

1. 将选定组已获得的完整单张图片复制或通过工具支持的方式导出到 `images/`，不要只写原位置的绝对路径，不把审阅拼图当首帧。保留该组选定的全部视角供下游审阅，但只将真正需要的图列为视频输入。未选组留在候选工作目录，不混入最终包。
2. `original-user-prompt.txt` 保存用户原始风格／照片提示词；图片提示词文件保存实际用于对应图片的完整提示词、父参考 ID 与模型信息。不能把后来修订但未运行的提示词冒充该图实际生成提示词；需要时另存修订版并标为待生成。
   自带图没有原图片提示词时，保存用户本次视频要求；逐图文件记录来源及「原始生成提示词未提供」。客观描述、重建建议与实际生成词分开，不要求重新生图。
3. `shot.md` 按 [镜头模板](../templates/shot.md) 填写全部 11 节，继承选定图的内容，补充相机、主体和环境运动。`prompts/video.txt` 是可独立复制的完整视频提示词，不依赖「见上文」或不存在的参考。只适配已核实的目标视频模型能力。
4. 从 [清单模板](../templates/handoff-manifest.json) 建立 `manifest.json`，填写选择证据、图片实际模型、视频目标模型、首帧、素材角色、相对路径、父参考、状态及输入模式。已生成图片和未生成视频分别记录状态。
5. `README.md` 说明用户选了什么、每张图的角色、图片实际模型与视频目标模型、提示词位置、输入顺序（仅能力已确认时）、未解决项及如何交给视频生成 AI。未知模式不编造槽位、参考张数上限、API 参数或负面字段。

## 清单字段约定

- `status`：`draft` 为未完成或模型未适配；`ready` 仅表示交付包文件与输入适配已检查，不表示视频已生成或视觉通过。
- `input_mode`：`generated_candidates`、`user_images` 或 `mixed`；模板初始为 null。
- `selection`：填写用户实际选定的组、首帧 ID、用户选择原文或简短来源，以及 n、m。没有用户选择不填写虚构证据；用户授权代选时写清该授权及实际选择。
  自带图无分组时 `group_id` 为 null，未请求生成候选时 n、m 为 null；单图「用这张做视频」可作为首帧选择依据。
- `image_model`：`requested` 是用户指定，`actual` 是工具实际返回；无法获知时为 null，`verification` 写「工具未披露」。多模型批次的总级 `actual` 可为 null，必须逐图记录实际信息。
- `video_model`：`target` 是目标名称；`actual` 在未生成视频时为 null。`capability_source` 与 `verification` 记录适配依据；无法核实则保持草案。
- `images`：每张含 `id`、`group_id`、`view`、`role`、`path`、`prompt_path`、`parent_id`、`actual_model`、`status`；主参考 `parent_id` 为 null。路径相对包根目录。首帧角色和身份／结构参考角色分开。
  每张另含 `source_type`（`user_provided` 或 `generated`）和 `provenance_note`（来源或未知说明）。自带图的 `prompt_path` 可指向来源说明文件；未知模型为 null；状态用 `provided_unreviewed` 或 `provided_reviewed`，不能写为本次生成。未知原始模型／提示词本身不阻塞 ready。
- `video_input`：`mode` 必须是已确认支持的模式或 `unverified`，`asset_ids` 仅列实际将绑定的图。全部视角都在包中不等于全部视角都要上传。
- `video_status`：没有生成视频时一直是 `not_generated`。图片生成成功不能改变此状态。

模板中的 null、空数组和 `unverified` 是尚未填写的状态，不是允许将完整交付包留空。缺图使用 null 路径和明确缺口，不创建假图片、空白占位图或伪文件路径。

## 无法收齐图片时

只有远程资源且无法合法导出到本地时，记录真实资源链接并说明缺少本地图片，标记 `draft`，提供下载／补齐需求。不能把仅含链接的包称为已包含全部图片；不要绕过环境媒体下载限制。需要生图但缺少工具时交付待生成计划，说明尚未完成的步骤；自带图已足够时，无需生成工具也可完成交付。

用户明确接受工具中立视频提示词时可以打包已有图片与草案，但 README、清单和回复都注明未适配目标模型。生成视频不是交付包的必要动作，不自动发起付费视频生成。

## 交付前检查

- 用户选择和 ID 对应，首帧属于选定组或自带图的选定集合；未擅自混入不同身份的素材。
- 每张已生成或自带图片路径存在、非空、格式正确，提示词或来源说明文件存在，父参考与模型记录如实填写；逐图查看后才写视觉结论。
- 每个清单路径位于包内，`video_input.asset_ids` 都能解析；图片本身独立保存，视频提示词和 shot.md 的首尾状态、配色、动作一致。
- 若模式已核实，输入数和图片角色符合实际工具；未核实则不标记为已适配。
- 提供文件夹链接并生成 ZIP，ZIP 解压后路径仍有效，不包含其他候选、密钥或无关项目文件。检查归档可读取、文件数和内容与交付文件夹相符。

最终回复给出真实图片预览、选定组／首帧、图片实际模型、视频目标模型、文件夹与 ZIP、是否仍有缺口。说明视频是否未生成，避免把「素材包已完成」误写为「视频已完成」。
