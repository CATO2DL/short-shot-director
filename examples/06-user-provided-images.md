# 自带图片：直接制作视频素材包

本例是流程说明，未附实际图片，未进行视觉检查或生成，不存在已完成的素材包。下文用户答复与文件 ID 是假设场景，不能当作真实选择证据。

## 单张图片

假设用户提供一张宫殿照片并说：「用这张做一个慢慢向右横移的视频，给我素材包。」

1. 查看真实附件，赋予 U01，记录来源为用户提供。若图像不可读，说明情况并请求可访问原图，不猜测画面。
2. 「用这张」已表明选择，U01 可作为首帧，不再问组数、视角数、图片模型或选哪张。
3. 询问目标视频模型；慢横移已明确，其他非阻塞参数可给建议。
4. 检查小幅横移是否会露出缺乏依据的结构；不需要新角度就不补图。若真实运动会绕到不可见侧面，先提出缺口或缩小运动建议。
5. 将实际 U01 原图、来源说明、完整横移视频提示词、11 节镜头文件和清单放入独立文件夹，再打包 ZIP。无需图片生成工具。

原图片模型和原始提示词没有提供时记为未知，不能从视觉风格推断。镜头中的图片提示词如有需要，明确为未执行的重建建议；视频依赖用户提供的原图。

## 多张图片与混合补图

假设用户带来产品正面与侧面两张图，但没有指定用途。查看并以 U01、U02 展示，第一轮问目标视频模型以及首帧／参考角色，不要求先重新生成 n×m 图片。

假设用户明确答复 U01 做首帧、U02 做结构参考，则保留这个绑定意图；只有工具实际支持相应输入模式时才给执行步骤。如果只支持首帧，U02 可作为审阅参考，不能谎称已绑定两张图。

用户后续要求绕到背面、现有图又没有背面资料时，再询问补图所用图片模型或请求真实背面照片。补图以已选主图派生，保留 `source_type: generated` 与父参考 U01；原图仍为 `user_provided`，交付包 `input_mode` 改为 `mixed`。真实产品隐藏结构不得随机补造。

## 检查点

- 单图选择明确后不重复选图，多图用途不明时再询问。
- 没有必要补图时，不问图片生成模型，不调用生成工具。
- 实拍、未知来源与本次生成的模型记录分开，原提示词未知不伪造。
- 原图不被重绘或覆盖；包中保存真实图片，无法导出时标明缺口。
- 视频没有实际生成时，始终记录 `video_status: not_generated`。
